# v0.0.2 Recommendations

These notes are intentionally saved for later work. They capture security, maintainability, and documentation improvements found while reviewing the current repository, SQL files, and `api.py`.

## Immediate Review Summary

- No database password was found in `api.py`.
- The original local API used hardcoded database host, database name, and user values.
- The committed API now reads PostgreSQL settings from environment variables.
- SQL schema, index, and starter query files are now present in `sql/`.
- The README and API docs now describe the current API instead of treating it only as future work.

## API Recommendations

- Add a real `/health` endpoint that checks API availability and database connectivity.
- Add response models with Pydantic so API output is documented and type-safe.
- Add pagination parameters instead of fixed `LIMIT 100` values.
- Add optional filters for host, source type, provider, event ID, severity, and time range.
- Add centralized database connection handling or a connection pool.
- Add structured error responses for database failures.
- Add CORS policy intentionally before exposing the API to a browser dashboard.
- Decide whether authentication is required before the API leaves a local lab environment.
- Avoid returning full event messages in unauthenticated contexts if they may contain sensitive command lines or usernames.

## Collector Recommendations

- Split `ingest.py` into modules after v0.1 stabilizes:
  - `collector/`
  - `api/`
  - `database/`
  - `parsers/`
  - `config/`
- Move event channel definitions into configuration.
- Add parser tests for Sysmon Event ID 1.
- Add database insert tests with a test database or mocked cursor.
- Add clearer handling for malformed XML and unexpected event fields.

## SQL Recommendations

- Add `003_constraints.sql` for nullable fields, uniqueness decisions, and referential expectations.
- Add `troubleshooting_queries.sql`.
- Consider storing `raw_data` as `JSONB` instead of `TEXT`.
- Consider indexes for common search fields after real query patterns are known.
- Consider a uniqueness strategy for `(source_host, source_type, event_record_id)` if duplicate prevention moves into the database.

## Documentation Recommendations

- Review `docs/02_Ingestion_Layer.md` against the final refactored collector.
- Review `docs/03_Database_Architecture.md` against the SQL files after constraints are added.
- Expand `docs/04_API_Reference.md` with example requests and responses.
- Add Mermaid diagrams for current architecture, target architecture, and event flow.
- Add screenshots after the API and future dashboard are running.
